# Региональные мероприятия: источники, v2

Разведка: 26.09.2026. Запросы шли по одному, с паузой 1,5 с и User-Agent из `lib/http.ts`. Код не менялся.
Предыдущая разведка: [regional-sources.md](regional-sources.md).

## Главный вывод

Официальные региональные соревнования ФСП (чемпионат, первенство и кубок субъекта) в основном **проводятся на
платформах-тренажёрах**. Там они уже описаны полями: название, дата, время, дисциплина. Алгоритмическое
программирование идёт почти целиком на **foncode.ru**, ИБ/CTF — на **caplag.ru**. Мероприятие публикуется там,
потому что на платформе проходит само соревнование, а не только анонс. Поэтому мусора нет: каждая строка —
состоявшийся контест.

Название на этих платформах почти всегда устроено как «Чемпионат/Первенство/Кубок + субъект». Субъект
определяется по названию той же функцией `findRegion`, что уже используется в коде. Всероссийские события
отсекаются по словам «Всероссийск», «Международн», «Межрегиональн» и «мира». Контакт организатора для продаж
берётся не из поста: субъект связывается с таблицей `federations` (руководитель и e-mail есть у всех 89 отделений).

Telegram остаётся нужен для того, чего нет на платформах: хакатонов, продуктового программирования,
робототехники и БАС, а также очных финалов с площадкой.

## Как отличать региональное от репоста и склеивать без LLM

1. **Субъект — из названия, а не из канала.** Для платформ: `findRegion(name)` по родительному падежу
   («Самарской области», «Республики Коми», «г. Москвы»). Для TG: если в названии поста найден *другой* субъект
   или его нет, а в тексте есть ссылка на caplag или foncode — это репост, запись не создаётся (fsp_RT/164,
   fsp_zo/327, fsp_saratov/34).
2. **Всероссийское отсекается по словам в названии** на платформах («Всероссийск», «Международн»,
   «Межрегиональн», «мира», «Цифровой атом»). Это надёжно, потому что названия официальные.
3. **Этапы в одно мероприятие.** Суффиксы «Отборочный этап», «Финал», «Пробный тур», «Тренировочный этап»,
   «Раунд 0», «(студенты)», «среди юношей…» отрезаются. Затем группировка по (субъект, база названия, год):
   dateFrom = min, dateTo = max.
4. **Склейка между источниками** — через уже существующий `linkEvents`. Ключ: субъект + тип
   (чемпионат / первенство / кубок / CTF / хакатон) + пересечение дат в окне ±14 дней. Приоритет источника:
   платформа > TG. TG-запись, совпавшая с платформенной, становится ссылкой-дополнением (пост с площадкой) и не
   считается отдельным мероприятием.
5. **Дубли анонса и итогов в TG** снимаются тем же ключом: пост «Результаты…» или «Определены финалисты…» —
   это не новое мероприятие, если за ±30 дней есть запись того же субъекта и типа.

## Какие поля реально получить

| Поле | Откуда |
|---|---|
| Название, даты | foncode, caplag (точно); TG (правила) |
| Дисциплина | caplag (поле); foncode (алгоритмика по умолчанию); TG (ключевые слова) |
| Онлайн/офлайн, формат участия | caplag (поле); foncode — всегда онлайн-этап |
| Число участников | caplag (на странице), Leader-ID |
| Город, площадка | только TG и Leader-ID (для очных финалов). Для отделения — город из `federations` |
| Организатор | региональная ФСП по субъекту (платформы в 100% случаев — ФСП или вуз-партнёр) |
| **Контакт организатора** | `federations`: руководитель и e-mail у 89/89, телефон — у 1 (на сайте ФСП других нет; см. ниже) |

## Рекомендация

Порядок подключения:

1. **Адаптер foncode.ru** — главный прирост: +9 субъектов, 0 мусора, точные даты. В синке — первые 1–2
   страницы (~2 МБ, <10 с), полный архив — разово при первом запуске (~40 с). Субъект — из названия,
   этапы склеиваются.
2. **Адаптер caplag.ru** — список и страница каждого соревнования (~10 запросов, <30 с). Регион — из названия
   или из ссылки на группу отделения в описании; иначе — `null` с пометкой «межрегиональное».
3. ~~Телефоны отделений со страниц регионов.~~ При внедрении выяснилось, что телефоны ЦФО на этих страницах —
   из статичного шаблона (`completed_pages/regiondetail`), а не текущие данные. Не подключаем.
4. **Telegram оставить, но сузить роль:**
   - «Мероприятие» создаётся только для хакатонов, продуктового программирования, робототехники и БАС, то есть
     того, чего нет на платформах. Посты про чемпионаты и кубки по алгоритмике и CTF не создают записей,
     а только дополняют платформенную запись ссылкой, городом и площадкой, если найдены.
   - Отсев репостов по субъекту в названии (п. 1 выше).
   - Удалить генерацию записей из постов-итогов и постов-регистраций, если за ±30 дней есть запись.
5. **VK** — только если появится `VK_SERVICE_TOKEN`: проверить ~50 кандидатов через `groups.getById`.
   Для поиска групп `groups.search` нужен пользовательский токен, а не сервисный. Без токена VK бесполезен
   (проверено: HTML без названия группы). Ожидаемый прирост в тех же категориях, что и TG, — невелик.
6. **Не подключать:** хакатоны.рус (заброшен), Codeforces gym, infosport, nwstep, календарные планы минспортов,
   TGStat (Cloudflare). Leader-ID и CTFtime — отложить: по ФСП-региональным мероприятиям они дают единицы
   событий. Но это возможный отдельный источник «организаторов хакатонов» (вузы, «Точки кипения») — если
   решите расширять воронку за пределы ФСП.

Что выбросить из текущего кода: извлечение даты «первая дата в тексте» для постов про алгоритмику и CTF (их
закроет foncode/caplag), `REGIONAL`-эвристику «хакатон = региональное» (даёт fspdnr/1528), дедуп внутри канала
только по датам (заменить общим ключом из п. 4 раздела о склейке).

Ожидаемый итог: ~29 мероприятий из платформ (16 субъектов, без мусора) + ~10–12 хакатонов и продуктовых
соревнований из TG ≈ **40 уникальных мероприятий из ~23 субъектов при мусоре <5%**. Сейчас — 40 записей, из
которых ~25 уникальных, 14 субъектов, мусор 37%. Бюджет синка — в пределах +1 мин (плюс 2,5 мин раз в неделю
на телефоны).

Риски: foncode за 2026 г. показывает меньше региональных контестов (19 строк против 47 в 2025 г.). Часть
регионов, возможно, ушла на Яндекс Контест, который публичного каталога не имеет. Это стоит отслеживать по
счётчику в `syncLog`.

## Региональные календарные планы (27.09.2026)

**АИС «Мой спорт»** (`org.moisport.ru/public-events-schedule`) — публичный единый календарный план субъектов, в
нём ведут планы минспорты регионов. Открытое JSON API без токена:
`/api/v1/public-events-schedule?searchSportTypeId=278&searchDateFrom=…` (278 — «Спортивное программирование» в
`/api/v1/sport-types`), карточка — `/api/v1/public-events-schedule/<id>` (этап комплексного —
`/complex/stages/<id>`).

- 341 мероприятие по виду спорта за 2023–2026, 39 субъектов; с 09.2025 — 201 мероприятие, 35 субъектов.
- Поля карточки: организатор (региональное отделение ФСП), уровень («Спортивное соревнование субъекта РФ»),
  ответственный, город/площадка, статус утверждения, иногда телефон и e-mail организатора.
- После отсева УТМ и всероссийских — 161 запись, 27 субъектов; из них 16 субъектов раньше не было ни в одном источнике.
- Даты в плане часто — окно («июнь – декабрь»), поэтому для отсева постов TG «Мой спорт» не используется;
  записи foncode/caplag/TG связываются с записью плана через `linkedId` («в плане субъекта»).

**Документы планов (PDF)** — `data/regional-plans.json`, разбор `plan-parse.ts`:
- текстовый PDF — `pdftotext -layout`; скан (меньше 100 букв на страницу) — `pdftoppm` 300 dpi + Tesseract
  `rus --psm 6` в TSV, слова раскладываются по колонкам по координатам (`ocrLayout`);
- строки раздела «Спортивное программирование» или со словом «программирование»; два макета таблицы
  (наименование в строке с номером / центрировано по вертикали) определяются по документу;
- проверка OCR: страницы саратовского плана, переведённые в картинки, дают те же 6 мероприятий (название, срок,
  город), что и текстовый PDF; ~1,8 с на страницу;
- документ кэшируется по sha256: OCR и разбор — только при смене файла.
